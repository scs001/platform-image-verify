# slim-unit-suite-runtime

## Why

unit 套件在冷 2 核 runner 上实测 **63 分钟**（run 42630983629）。这个数字已经很危险：
作业上限 90 分钟时只剩 ~27 分钟给 build + e2e，一次慢就会被 job kill，而那种红在报告里
和"产品坏了"长得一模一样（2026-11-09 已因此误判两次，一次归咎于"资源饥饿"、
一次归咎于"某条用例悬挂"）。

**这不只是"慢"，它已经是门禁自身的吞吐上限**（2026-11-09 实测）：镜像仓的 concurrency
是 QUEUED（`queue-release-ci-runs`），而每次快照推送都排一次 unit。快照 `6f963a019`
的 CI 从 14:46:55Z 起跑，超过 60 分钟未完成，更新的 `ffc8168b0` 已经排在它后面。推送间隔
10–30 分钟 vs 单次 unit 60+ 分钟 ⇒ **CI 队列只增不减**，强制门禁反而积压。把作业上限抬到
120 分钟只够一次运行，治不了队列增长。

**`--test-timeout` 是"抓悬挂"不是"提速"，已实测**（2026-11-09，五条各睡 3 秒的用例）：

| 配置 | 总耗时 | 结果 |
|---|---|---|
| 无超时 | 15.33s | 5/5 通过 |
| `--test-timeout=1000` | **7.25s** | 五条**各 1 秒点名失败** |

即：它把**每条**用例压在 1 秒，但它是逐条上限、不是总时长上限。所以 63–81 分钟的步骤
不能归咎于"超时没生效"——是几百条用例各自合规地累加。180 秒对正常用例毫无约束力（只抓悬挂），
**能降总时长的唯一杠杆是条数与启动成本**。

**成因是集中的，不是普遍的**：489 个测试文件里 **58 个**会起真实 server 或 dsh 子进程
（`spawnTestServer` / `initTaskEngine` / `attachAgentSession`），每个都付一次子进程启动。
12% 的文件构成主要成本，所以"把 489 个文件平均切开"不是对症解法。

**三条既得事实（本轮实测，避免下一轮重新发现）**：

1. **`--test-shard` 不能用**。它切的是**扁平化的用例列表**，不是文件列表：四个文件时
   shard 1/2 里同时出现 `browser-lane-artifacts` 与 `queue-health` 的用例。同一文件的用例
   会落到不同 runner **并发跑**，而 `--test-concurrency=1` 存在的理由正是文件内顺序依赖
   （queue-health 的"遗留 queued 记录不泄漏"只有在前面的用例先跑过才有意义）。
   已用断言钉住（`scripts/test-unit-shard-safety.mjs`）：`test:unit` 不得出现 `--test-shard`。
2. **停摆形态与"悬挂"不同**。一处早期判断（"某条用例卡死"）已被推翻：`--test-timeout=180000`
   确实生效，63 分钟是**大量慢用例累加**，不是单条无限等。
3. **缩容先量**。node 的 reporter 不带文件名（TAP 顶层 subtest 是单条用例），所以
   per-file 榜单只能逐进程计——工具已就位：`scripts/profile-unit.mjs`
   （默认自动挑那 58 个 spawn 重的文件；带两道前置检查，拒绝在无依赖或软链依赖的树上跑）。

## What Changes

本轮**只立契约不改造**——把问题、真因、已排除解法、量尺写进台账，让下一轮照数据动手，
而不是重新摸索一遍。

## Capabilities

（无 —— 本单不改变任何产品行为，纯工程性能议题。）

## 非目标

- **不改 CI 拓扑**：作业上限已由 90 提到 120 分钟作为止损（`a4f162950`），够用一阵。
- **不动 `--test-shard`**：已证不可用，理由见上并已入闸。
- **不裁用例**：没量出谁是慢源之前不动刀——`profile-unit.mjs` 就是为此准备的。
- **不重构 58 个 spawn 套件**：那是本单的后续工作，需要先有 per-file 榜单。

## 后续（本单不执行）

1. 跑 `node scripts/profile-unit.mjs`（在**有真实依赖**的主树里）拿到 58 个文件的耗时榜单。
2. 按榜单决定：给最慢的几个简化 boot / 提供共享 server fixture / 移到独立 CI 车道。
3. 若要分片，必须**自己按 `ls scripts/test-*.mjs` 切文件列表**，并加断言
   「已执行文件并集 == 全集」——绝不能用 `--test-shard`。
